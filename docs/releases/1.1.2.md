Endpoint Toolbelt 1.1.2 adds Check Defender blocks, an HTML report for IT support, a notice when a
newer version exists, and Retry work apps and settings in For IT support. It reorders For IT support
into six groups, and it fixes the post-check of apps offered in Company Portal. Endpoint Toolbelt
lets employees and IT support find out why a work app won't install or why Windows Update keeps
failing, fix the common causes themselves, and hand the rest to IT support with the evidence
attached.

## What changed

- **Check Defender blocks** (For IT support, Defender & security). It reads what Microsoft Defender
  logged in the last 14 days, without changing anything:
  - threat detections;
  - attack surface reduction rules;
  - controlled folder access;
  - network protection.

  It shows one card per thing that was stopped, with what IT support needs for an exclusion, an
  allowed app or an indicator. With Microsoft Defender Antivirus active it also says:
  - when the last quick and full scan ended;
  - whether protection was switched off in the last 14 days;
  - a change that tamper protection blocked;
  - a failed update.

  Other users' events are counted only. The status line stays short ("Microsoft Defender
  blocked or detected something in the last 14 days. See the details."); the counts are in the
  details. A new read-only service action, `CheckDefenderBlocks`, can be switched off with
  `DisabledTools`.
- **Export HTML** (For IT support). It first runs the read-only checks: the app diagnosis, Check
  Windows Update, Check Defender blocks, Check Microsoft connections and Check compliance settings.
  It then saves the device report as one web page in Downloads and opens it. The page has:
  - a table of contents and a summary;
  - the result and time of every check;
  - every work app, the ones that need attention first.

  The page holds no script and loads nothing from elsewhere.
- **A notice when a newer version exists.** Once a day the app reads one small file from the publisher's site.
  If a newer version exists, it shows a notice at start-up, with a link to its release notes, and
  About names it.
  - The app never downloads or installs anything itself.
  - The request carries no data about the device or the user; the site sees the internet address
    and the time, as every website does.
  - Switch it off in About (per user), on the installer's first screen, with `UPDATECHECK=0` on a
    silent install, or with the policy value `UpdateCheck` = 0 (for everyone).
- **Retry work apps and settings in For IT support.** It is the first tool of Apps, so it can be
  started at once. Its page says how the work apps stood at the last check, for example "2 of 14
  work apps need attention (...)", with Show the apps to the full list. It cannot be switched off.
  A Retry started before the app read the work apps reads them first, so it is checked afterwards.
- **For IT support in six groups.** The groups are Apps, Sign-in, Microsoft 365, Windows, Defender
  & security, and Network & storage. Each has a coloured icon, and the three report buttons sit in
  one row. A tool row or tile shows a result of the last 24 hours only.
- **A check's answer shows at once.** Check Defender blocks, Check Windows Update, Check Microsoft
  connections and Check compliance settings say their answer in a sentence when they end.
- **Upgrade with the app open.** The setup says the app is open and offers Close it and continue,
  instead of Windows' Retry, Ignore and Exit. Install screens show progress, and they say when the
  install is done, when the package is already installed, and when it failed.
- **Repair Windows Update** follows Microsoft's list of common Windows Update errors for more
  codes.
- **Fixes:**
  - After Retry work apps and settings, an app offered in Company Portal no longer reads "Awaiting
    evidence" for a week. The app installer never retries such an app; only Install or Retry in
    Company Portal does.
  - After a post-check or a Retry, the status no longer reads OK or "Done" while other apps still
    need attention.
  - A succeeded Office installation is no longer listed as a failed configuration setting.

## Download and verify

`EndpointToolbelt-1.1.2-x64.msi` and its `.sha256` are attached below. The MSI and the
executables and assemblies in it are signed by SoulBit, with a timestamp. The signing certificate
names SoulBit (`O=SoulBit`) and is renewed daily, so compare the subject, not the thumbprint.

```powershell
(Get-FileHash .\EndpointToolbelt-1.1.2-x64.msi -Algorithm SHA256).Hash   # compare with the .sha256
Get-AuthenticodeSignature .\EndpointToolbelt-1.1.2-x64.msi | Format-List Status, SignerCertificate
```

## Install or upgrade

1.1.2 replaces 1.0.0 and 1.0.1 in place; settings, results and history stay. In Intune, add it as
a new Windows app (Win32) with an MSI detection rule for its own product code, installed as
System. Set supersedence on the earlier app with *Uninstall previous version* off:

```cmd
msiexec /i EndpointToolbelt-1.1.2-x64.msi /qn
```

To leave the version check off on a silent install, add `UPDATECHECK=0`.

Start with the [admin guide](https://github.com/soulbit-nl/endpoint-toolbelt/blob/v1.1.2/docs/admin-guide.md)
and the [deployment guide](https://github.com/soulbit-nl/endpoint-toolbelt/blob/v1.1.2/docs/deployment.md).

## Tested

In Windows Sandbox, on a build of the release source: 848 checks, all passed.
- The MSI: install with configuration, repair, uninstall and downgrade refusal; the install
  screens; the upgrade from the published 1.0.1 MSI; and the upgrade with the app open, where the
  setup closes it.
- The service, the engine and the app as a standard user through every page, tool and action, in
  the light, dark and high-contrast themes, offline, behind a proxy and with a restart waiting.
- Free up disk space was run up to its confirmation, not through its full cleanup, which this
  release does not change.

On real devices, with earlier candidates of this release: an Entra-joined laptop (For IT support,
Export HTML, Check Defender blocks with threat detections, rule blocks and controlled folder
access) and an Azure Virtual Desktop host (Check Defender blocks with network protection, the
Retry tool, the app diagnosis with apps offered in Company Portal). Two faults they found were
fixed: an upgrade with the app open showed Windows' own Retry, Ignore and Exit (the fix is proven
in Windows Sandbox, from 1.0.0 and 1.0.1), and apps offered in Company Portal kept "Awaiting
evidence" after a Retry (the fix is proven in tests).

### Not tested

- An install by a double-click without administrator rights with "Check for new versions at
  start-up" cleared. The Sandbox runs the setup elevated, so the property `UPDATECHECK` was
  only proven there and with `/qn`.
- Eight Defender health events (5000, 5001, 5010, 5012, 3002, 2001, 2003 and 2004) occurred on
  none of the devices, so their texts rest on Microsoft's event descriptions only.
- An upgrade from 1.0.1 through Intune (supersedence). The upgrade itself was tested in the
  Sandbox and by hand.
- A test with people outside IT.
- The [known limitations of 1.0.0](https://github.com/soulbit-nl/endpoint-toolbelt/blob/v1.0.0/docs/releases/1.0.0.md#known-limitations)
  still apply.
