Endpoint Toolbelt 1.0.1 fixes what an external review of 1.0.0 found, and adds the publisher's
links to Programs and Features. Endpoint Toolbelt lets employees and IT support find out why a
work app won't install or why Windows Update keeps failing, fix the common causes themselves, and
hand the rest to IT support with the evidence attached.

## What changed

- **Restart status that cannot be read is no longer "OK".** When Windows' restart flags cannot be
  read, the restart check shows the warning "Restart status unknown" instead of "No restart
  pending". It does not claim that a restart is waiting either, and its step is to check again.
- **Retry work apps and settings says what it did.** While other people are signed in, the app
  installer is not restarted and its retry timers are kept. The status now says "Sync requested"
  instead of "Retry requested", and the log no longer says that the app installer restarted.
- **Links in Programs and Features.** The MSI names the publisher's site and the source with its
  documentation, the same two links as the About dialog.
- **Docs.** The admin guide asks for evidence before an attack surface reduction rule is taken as
  the cause of install error 1920 (Defender event 1121), and points to the MSI log otherwise.

## Download and verify

`EndpointToolbelt-1.0.1-x64.msi` and its `.sha256` are attached below. The MSI and the
executables and assemblies in it are signed by SoulBit, with a timestamp. The signing certificate
names SoulBit (`O=SoulBit`) and is renewed daily, so compare the subject, not the thumbprint.

```powershell
(Get-FileHash .\EndpointToolbelt-1.0.1-x64.msi -Algorithm SHA256).Hash   # compare with the .sha256
Get-AuthenticodeSignature .\EndpointToolbelt-1.0.1-x64.msi | Format-List Status, SignerCertificate
```

## Install or upgrade

1.0.1 replaces 1.0.0 in place; settings, results and history stay. In Intune, add it as a new
Windows app (Win32) with an MSI detection rule for its own product code, installed as System, and
set supersedence on the 1.0.0 app with *Uninstall previous version* off:

```cmd
msiexec /i EndpointToolbelt-1.0.1-x64.msi /qn
```

An upgrade keeps the configuration of 1.0.0. A setting on the command line (for example
`SUPPORTURL`) replaces the stored value, so pass one again only to change it.

Start with the [admin guide](https://github.com/soulbit-nl/endpoint-toolbelt/blob/v1.0.1/docs/admin-guide.md)
and the [deployment guide](https://github.com/soulbit-nl/endpoint-toolbelt/blob/v1.0.1/docs/deployment.md).

## Tested

The full Windows Sandbox suite on the release MSI, and the 1.0.0 MSI through an independent
packaging test (install, repeat install, repair, uninstall, standard user and launch) on a
Windows 11 virtual machine with memory integrity on. The fixes in this release were not tried on
the three real devices of 1.0.0 again; the
[known limitations of 1.0.0](https://github.com/soulbit-nl/endpoint-toolbelt/blob/v1.0.0/docs/releases/1.0.0.md#known-limitations)
still apply.
